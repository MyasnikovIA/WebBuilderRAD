# # `Инструкция по созданию компонентов


# Инструкция для создания D3-компонентов в IDE WebBuilder RAD

Документ описывает архитектуру IDE, правила регистрации компонентов, обязательные правки в ядре и типовые паттерны. Следуя ему, можно добавлять новые D3-компоненты, аналогичные существующим.

---

## 1. Общая архитектура

### 1.1. Что такое D3-компонент

D3-компонент — это пара:
- **Серверный класс** (`.inc`) — рендерит HTML-разметку в рантайме, читает атрибуты из XML.
- **Клиентский контрол** (`.js`) — `D3Api.<Name>Ctrl`, управляет поведением в браузере.

В RAD-редакторе (IDE) компонент представлен:
- **Регистрацией** через `D3.register(...)` в `Component/d3/<Name>/index.js`.
- **Опциональным превью-CSS** в `Component/d3/<Name>/css/preview.css`.
- **Иконкой** в `Component/d3/<Name>/images/icon.png`.
- **Опциональным preview-JS** в `Component/d3/<Name>/js/preview.js`.

### 1.2. Как устроен рабочий процесс

```
Пользователь в IDE → палитра → insertComponent()
    ↓
create(doc) → создаёт DOM-элемент <cmpName>
    ↓
Canvas.insertComponent → appendChild в целевой контейнер
    ↓
_renderPreview(el) → вызывает def.preview(el, doc)
    ↓
preview-узел [data-wb-preview="1"] добавляется в el
    ↓
При сохранении: _purgeServiceNodes удаляет все [data-wb-ide]/[data-wb-preview]
    ↓
_formatNode сериализует «чистый» элемент в XML
```

### 1.3. Три категории компонентов

| Категория | Примеры | Видим в canvas | preview() |
|---|---|---|---|
| **Видимые контролы** | `CheckBox`, `ComboBox`, `Edit`, `DateEdit`, `File`, `Grid`, `FieldSet`, `InfoBox`, `HyperLink`, `Image`, `InfoAboutRecord` | Да | Да (реальный превью-узел или обновление chrome в create) |
| **Служебные (невидимые)** | `Action`, `DataSet`, `Script`, `Mask`, `Broker`, `Comment`, `Completer`, `Dependences`, `Fetch`, `FetchVar` | Нет | `null` |
| **Корневые контейнеры** | `cmpForm`, `RootDiv`, `SubForm` | Да (но особым образом) | `null` или chrome через CSS |

## 2. Структура папки компонента

```
Component/d3/<Name>/
    index.js               ← обязательный: регистрация D3.register
    images/icon.png        ← 14×14, для палитры (класть вручную)
    css/preview.css        ← опционально: стили превью
    js/                    ← опционально: preview.js (редко нужно)
```

**Правила:**
- Имя папки = `folderOf(tagName)`: `cmpComboBox` → `ComboBox`.
- Иконка и CSS подключаются через относительные пути (`'images/icon.png'`, `'css/preview.css'`); `D3.register` превращает их в абсолютные.
- Папка `js/` обычно пустая. Заполняется только если нужен интерактивный preview.

## 3. API `D3.register(opts)`

Полный набор опций:

```js
D3.register({
    // --- Обязательные ---
    id: 'd3.checkbox',              // уникальный ID, обычно d3.<lowercase>
    tagName: 'cmpCheckBox',         // XML-тег, camelCase с префиксом cmp
    caption: 'CheckBox',            // подпись в палитре

    // --- Опциональные ---
    icon: 'images/icon.png',        // относительный путь от папки компонента
    previewCss: ['css/preview.css'],// массив относительных путей
    previewJs: ['js/preview.js'],   // массив относительных путей
    hidden: false,                  // скрыть в палитре (для корневых)
    unique: false,                  // разрешён только один экземпляр
    parentOnly: 'cmpcombobox',      // можно вставить только внутрь указанного тега
                                    // (может быть массивом: ['cmpaction','cmpsubaction'])

    // --- Функции ---
    attrs: { name: '', value: '' }, // атрибуты по умолчанию (setAttribute при create)
    create: function (doc) { ... }, // своя реализация создания элемента
    preview: function (el, doc) { ... }, // возвращает preview-узел или null

    // --- Схема инспектора ---
    properties: [ ... ],            // вкладка Properties
    events: [ ... ],                // вкладка Events
    styles: [ ... ]                 // вкладка Styles
});
```

### 3.1. Дефолтный `create` (если не задан)

```js
function (doc) {
    var el = doc.createElement(tagLower);
    el.setAttribute('data-wb-tag', tagName);   // ОБЯЗАТЕЛЬНО
    for (var k in opts.attrs) el.setAttribute(k, opts.attrs[k]);
    if (opts.cdata != null) el.appendChild(doc.createTextNode('<![CDATA[' + opts.cdata + ']]>'));
    return el;
}
```

**Ключевой момент:** `data-wb-tag` — маркер, по которому `ComponentRegistry.match(el)` находит определение. Без него компонент будет считаться `html.generic`.

### 3.2. `preview(el, doc)`

Возвращает:
- **DOM-узел** — `_renderPreview` обернёт его в `[data-wb-preview="1"]` и добавит в `el`.
- **`null`** — `_renderPreview` не добавит ничего (но перед этим удалит старый preview-узел).
- **Строку HTML** — `_renderPreview` превратит в узел через `tmp.innerHTML`.

**Побочные эффекты допустимы.** Можно возвращать `null`, но при этом обновлять что-то в самом `el` или в chrome-узлах — этот приём используется, когда структура компонента построена в `create()`, а `preview()` только синхронизирует её с атрибутами.

### 3.3. `properties` — разделы инспектора

Каждое поле:
```js
{ name: 'value', caption: 'Value', type: 'string', attr: true }
```

| `type` | Поведение |
|---|---|
| `string` | `<input type="text">`, читает/пишет `el.getAttribute(name)` (если `attr: true`) или `el[name]` |
| `number` | `<input type="number">` |
| `boolean` | `<input type="checkbox">`, `attr: true` ставит `name="true"` / удаляет |
| `enum` | `<select>`, требует `values: [...]` |
| `color` | `<input type="color">` + текстовое поле |
| `length` | number + unit (`px`, `%`, `em`, `rem`, `pt`, `auto`) |
| `text` | `<textarea rows="3">` |
| `code` | кнопка **Edit…**, открывает модальное окно с редактором кода |
| `image` | текстовое поле + кнопка выбора |
| `images` | кнопка редактирования карты картинок (требует `D3.openImagesEditor`, может быть не реализован) |
| `separator` | визуальный разделитель группы, `{ type: 'separator', caption: '…' }` |

**Кастомные get/set:**
```js
{
    name: 'value', caption: 'Value', type: 'string', attr: true,
    get: function (el) { return el.getAttribute('value') || ''; },
    set: function (el, v) { el.setAttribute('value', String(v)); }
}
```

Используется, когда поле не совпадает напрямую с атрибутом (например, `caption` хранится в атрибуте, но его удобнее читать/писать особым образом).

### 3.4. `events` — вкладка Events

Каждое событие:
```js
{ name: 'onclick', caption: 'OnClick', type: 'code' }
```

Значение хранится как атрибут `onclick="…"` на элементе.

**Расширенные опции:**

```js
{
    name: 'onclick',
    caption: 'OnClick',
    type: 'code',
    template: 'Form.{name} = function(dom) {\n\n};'   // опционально
}
```

| Опция | Тип | Описание |
|---|---|---|
| `name` | `string` | Имя HTML-атрибута (`onclick`, `ondblclick`, …). |
| `caption` | `string` | Заголовок в инспекторе. |
| `type` | `string` | Для событий всегда `'code'`. |
| `template` | `string` | **Опционально.** Шаблон тела JS-функции, которая создаётся при двойном клике на выпадающий список событий, если ничего не выбрано. |

**Как работает вкладка Events:**

Каждое событие рендерится в инспекторе как пара контролов:

```
[ input: <значение атрибута>              ] [ select: список функций формы ▼ ]
```

- **input** — текущее значение атрибута, редактируется вручную.
- **select** — список всех JS-функций формы (из `cmpScript` / inline `<script>`), с готовыми сигнатурами вызова.

**Поведение:**

| Действие | Что происходит |
|---|---|
| Изменение `input` | Значение применяется к элементу (атрибут `on*`). |
| Двойной клик по `input` | Открывается модальное окно `CodeEditor` (JS-подсветка). После ОК значение пишется обратно в `input`. |
| Выбор в `select` | Сигнатура копируется в `input` (затирая старое), применяется к элементу. |
| Двойной клик по `select` (есть значение) | Открывается вкладка **Code**, курсор позиционируется на объявлении этой функции. |
| Двойной клик по `select` (пусто + `input` пуст) | **Создаётся новая функция** в первом найденном `cmpScript` / inline `<script>`. Имя генерируется автоматически; шаблон берётся из `template` (или из дефолта). Сигнатура подставляется в `input` и применяется. |

### 3.4.1. Шаблон функции события (`template`)

Поле `template` задаёт, **какое тело функции генерируется**, когда пользователь двойным кликом по `select` создаёт новую функцию.

**Плейсхолдеры:**

| Плейсхолдер | Значение |
|---|---|
| `{name}` | Полное имя функции без префикса `Form.` — например `onClickBtn`. Состоит из `on` + CamelCase(события) + `name`/`id` контрола. |
| `{event}` | CamelCase названия события без `on` — например `Click`, `MouseDown`. |
| `{ctrl}` | Значение атрибута `name` контрола, иначе `id`, иначе пусто. |

**Дефолтное поведение (если `template` не задан):**

- Если найден блок `cmpScript` (или создаётся новый) → генерируется:
  ```
  Form.<event><Ctrl> = function(dom) {

  };
  ```
- Если найден обычный inline `<script>` → генерируется:
  ```
  <event><Ctrl> = function(dom) {

  };
  ```

**Как задать свой шаблон:**

```js
D3.register({
    // ...
    events: [
        {
            name: 'onclick',
            caption: 'OnClick',
            type: 'code',
            template: 'Form.{name} = function(dom) {\n    // TODO: {event} on {ctrl}\n};'
        },
        {
            name: 'onchange',
            caption: 'OnChange',
            type: 'code'
            // template не задан → сработает дефолт
        }
    ],
    // ...
});
```

**Правила:**

- Шаблон — обычная JS-строка с переносами `\n`.
- Отступы: код вставляется в CDATA с отступом по контексту (`_formatCmpNode` нормализует отступы при сохранении).
- Если в шаблоне есть `Form.` — считается, что это функция формы (`cmpScript`).
- Если `Form.` нет — считается, что это свободная функция (`<script>`).
- Ключевые слова `function`, `=>` и т.п. IDE не парсит — что написали, то и вставится.

**Примеры:**

**1. Стандартный onclick (Form-функция):**

```js
{
    name: 'onclick', caption: 'OnClick', type: 'code',
    template: 'Form.{name} = function(dom) {\n    \n};'
}
```

Результат в `cmpScript`:

```js
Form.onClickBtn = function(dom) {
    
};
```

**2. Свободная функция (не Form):**

```js
{
    name: 'onclick', caption: 'OnClick', type: 'code',
    template: '{name} = function(event) {\n    console.log(event);\n};'
}
```

Результат в `<script>`:

```js
onClickBtn = function(event) {
    console.log(event);
};
```

**3. Обработчик с несколькими аргументами:**

```js
{
    name: 'onkeydown', caption: 'OnKeyDown', type: 'code',
    template: 'Form.{name} = function(dom, event) {\n    if (event.keyCode === 27) return;\n};'
}
```

**4. Обработчик с обращением к this:**

```js
{
    name: 'onmousedown', caption: 'OnMouseDown', type: 'code',
    template: 'Form.{name} = function(_this, event) {\n    _this.classList.add("active");\n};'
}
```

**5. Без `template` — дефолт:**

```js
{ name: 'onchange', caption: 'OnChange', type: 'code' }
```

При двойном клике на пустой `select` в `cmpScript` появится:

```js
Form.onChangeCtrl1 = function(dom) {

};
```

### 3.5. `styles` — вкладка Styles

Обычно:
```js
styles: CS.STYLE_FIELDS.slice()
```
где `CS = global.CommonSchema`. Это стандартный набор CSS-свойств (display, position, width, height, margin, padding, backgroundColor, color, fontFamily, fontSize, …). Все они читаются/пишутся через `el.style[field.name]`.

Для служебных компонентов можно `styles: []` — секция будет пустой.

## 4. Специальные маркеры DOM

### 4.1. `data-wb-tag="cmpXxx"`

Обязательный атрибут на корне компонента. Используется:
- `ComponentRegistry.match(el)` — поиск определения.
- `_formatTagName(el)` — при сериализации в XML имя тега берётся отсюда.
- `DomTree._label` — подпись узла в дереве.

### 4.2. `data-cmptype="d3.xxx"`

Опционально. Используется `ComponentRegistry.match` в первую очередь, если задан.

### 4.3. `data-wb-ide="1"`

**Chrome-узел.** Виден в canvas, не сериализуется, не появляется в дереве.

Применение:
- Легенда `FieldSet`.
- Шапка/подвал `Dialog`.
- Зона клика `Expander`.
- Служебные ярлыки.

Удаляется `_purgeServiceNodes` при сохранении. Пропускается `DomTree._build`.

### 4.4. `data-wb-preview="1"`

**Preview-узел.** Создаётся `_renderPreview` автоматически, если `preview()` вернул DOM-узел. Удаляется `_purgeServiceNodes`. Пропускается `DomTree._build`.

### 4.5. `data-part="…"` / `data-wb-root="1"`

Произвольные маркеры для поиска chrome-узлов внутри компонента. Никак не влияют на ядро, используются внутри `preview()`.

## 5. Сценарии и паттерны

### 5.1. Видимый компонент с preview-узлом

**Пример:** `CheckBox`, `ComboBox`, `Edit`, `DateEdit`, `InfoBox`, `HyperLink`, `Image`, `File`.

```js
D3.register({
    id: 'd3.checkbox', tagName: 'cmpCheckBox', caption: 'CheckBox',
    icon: 'images/icon.png',
    previewCss: ['css/preview.css'],
    attrs: { name: '', value: '' },
    create: function (doc) {
        var el = doc.createElement('cmpcheckbox');
        el.setAttribute('data-wb-tag', 'cmpCheckBox');
        return el;
    },
    preview: function (el, doc) {
        var wrap = doc.createElement('span');
        wrap.className = 'd3-preview d3-preview-checkbox';
        wrap.textContent = el.getAttribute('caption') || '';
        return wrap;
    },
    properties: [ /* … */ ],
    events: [ /* … */ ],
    styles: CS.STYLE_FIELDS.slice()
});
```

`preview()` вызывается при:
- создании компонента через палитру,
- изменении любого атрибута через инспектор,
- явном `canvas.refreshPreview(el)`.

### 5.2. Видимый компонент с chrome в `create()`

**Пример:** `Dialog`, `FieldSet`, `Expander`.

Когда визуальная структура сложная и её не хочется пересобирать на каждый `preview()`:

```js
create: function (doc) {
    var el = doc.createElement('cmpdialog');
    el.setAttribute('data-wb-tag', 'cmpDialog');

    /* Chrome-узлы помечаем data-wb-ide="1" — не сериализуются. */
    var header = mkChrome(doc, 'header');
    header.appendChild(mkChrome(doc, 'caption', 'Заголовок'));
    el.appendChild(header);

    /* Пользовательские дети попадут после header через appendChild. */
    return el;
},
preview: function (el) {
    /* Обновляем chrome по атрибутам. Возвращаем null — preview-узел не нужен. */
    var header = el.querySelector('[data-part="header"]');
    header.textContent = el.getAttribute('caption') || '';
    return null;
}
```

### 5.3. Служебный (невидимый) компонент

**Пример:** `Action`, `DataSet`, `Script`, `Mask`, `Comment`, `Completer`, `Dependences`, `Fetch`.

```js
D3.register({
    id: 'd3.action', tagName: 'cmpAction', caption: 'Action',
    icon: 'images/icon.png',
    preview: null,                        // ← невидим
    attrs: { name: '' },
    properties: [ /* … */ ],
    events: [],
    styles: []
});
```

**Обязательно:** добавить тег в `_injectIdeStyle` в `canvas.js`, чтобы он не отображался:

```js
'cmpaction, cmpdataset, cmpscript, cmpmask, cmpbroker, cmpcomment, cmpcompleter, cmpdependences, cmpfetch, cmpfetchvar {' +
'  display: none !important; visibility: hidden !important;' +
'  pointer-events: none !important; user-select: none !important;' +
'}'
```

### 5.4. Контейнер с детьми (parentOnly)

**Пример:** `ComboBox` → `ComboItem`, `Grid` → `Column` / `GridFooter`, `Filter` → `FilterItem`, `Fetch` → `FetchVar`.

```js
D3.register({
    id: 'd3.comboitem', tagName: 'cmpComboItem', caption: 'ComboItem',
    parentOnly: 'cmpcombobox',   // можно вставить только внутрь cmpComboBox
    // ...
});
```

**Обязательно** добавить в `PARENT_ONLY` в `panels.js`:

```js
var PARENT_ONLY = {
    cmpactionvar:    ['cmpaction', 'cmpsubaction'],
    cmpdatasetvar:   'cmpdataset',
    cmpfetchvar:     'cmpfetch',
    cmpcomboitem:    'cmpcombobox',
    cmpfilteritem:   'cmpfilter',
    cmpcolumn:       'cmpgrid',
    cmpgridfooter:   'cmpgrid',
    cmptagitem:      'cmpbuttonedit'
};
```

Это включает проверку при drag&drop в дереве (`DomTree._canDrop` использует именно `PARENT_ONLY`, а не `def.parentOnly`).

### 5.5. Самозакрывающийся тег

**Пример:** `cmpActionVar`, `cmpDataSetVar`, `cmpFetchVar`, `cmpComboItem`, `cmpImage`.

В рантайме сервер рендерит их как `<var …/>`, `<img …/>`. При сохранении IDE должна выдавать то же:

```js
// canvas.js
var XML_SELF_CLOSE = {
    cmpactionvar:1, cmpdatasetvar:1, cmpcomboitem:1, cmpsubactionvar:1,
    cmpfetchvar:1, cmpsubfetchvar:1, cmpimage:1,
    'wb-image':1, cmptagitem:1
};
```

`_formatNode` для таких тегов выдаст `<cmpImage …/>` вместо `<cmpImage …></cmpImage>`.

### 5.6. CDATA-контейнеры

**Пример:** `cmpAction`, `cmpDataSet`, `cmpScript`, `cmpSubAction`.

В этих элементах основной контент — CDATA-блок. В IDE хранится как текстовый узел с обёрткой `<![CDATA[…]]>`:

```js
// canvas.js
var CDATA_CONTAINERS = { cmpaction:1, cmpdataset:1, cmpscript:1, cmpsubaction:1 };
```

`_formatNode` вызовет `_formatCmpNode`, который аккуратно отформатирует CDATA с отступами. Для редактирования используется свойство `cdata` (тип `code`):

```js
{
    name: 'cdata', caption: 'CDATA', type: 'code',
    get: function (el) {
        var t = el.textContent || '';
        var m = t.match(/^<!\[CDATA\[([\s\S]*?)\]\]>$/);
        return m ? m[1] : t;
    },
    set: function (el, v) {
        el.textContent = '<![CDATA[' + (v == null ? '' : v) + ']]>';
    }
}
```

### 5.7. Хранение JSON в тексте

**Пример:** `CustomFilter`.

Когда на сервере данные передаются через `SetInnerText`, а IDE должна их редактировать как JSON:

```js
function getJson(el) {
    var out = '';
    var kids = el.childNodes;
    for (var i = 0; i < kids.length; i++) {
        if (kids[i].nodeType === 3) out += kids[i].nodeValue;
    }
    return out;
}
function setJson(el, v) {
    /* Удалить все текстовые узлы, вставить новый. */
    var kids = el.childNodes;
    for (var i = kids.length - 1; i >= 0; i--) {
        if (kids[i].nodeType === 3) el.removeChild(kids[i]);
    }
    el.insertBefore(el.ownerDocument.createTextNode(v == null ? '' : String(v)), el.firstChild);
}
```

В `properties`:
```js
{ name: 'text', caption: 'JSON', type: 'code',
  get: getJson, set: setJson }
```

### 5.8. События с индивидуальным шаблоном функции

**Пример:** любая кнопка (`cmpButton`), у которой хочется генерировать осмысленное имя функции-обработчика.

```js
D3.register({
    id: 'd3.button', tagName: 'cmpButton', caption: 'Button',
    // ...
    events: [
        {
            name: 'onclick',
            caption: 'OnClick',
            type: 'code',
            template: 'Form.on{name}Click = function(dom) {\n    \n};'
        },
        {
            name: 'ondblclick',
            caption: 'OnDblClick',
            type: 'code',
            template: 'Form.on{name}DblClick = function(dom) {\n    \n};'
        },
        {
            name: 'onmousedown',
            caption: 'OnMouseDown',
            type: 'code'
            /* template не задан → сработает дефолт */
        }
    ],
    // ...
});
```

При двойном клике по пустому `select` в инспекторе:
- для `OnClick` в первом `cmpScript` появится `Form.onMyButtonClick = function(dom) { };`
- для `OnDblClick` — `Form.onMyButtonDblClick = function(dom) { };`
- для `OnMouseDown` — дефолт `Form.onMouseDownMyButton = function(dom) { };`

### 5.9. Корневой контейнер

**Пример:** `cmpForm`.

```js
D3.register({
    id: 'd3.form', tagName: 'cmpForm', caption: 'Form',
    unique: true, hidden: true,   // обязательны оба
    preview: null,
    // ...
});
```

Создаётся через `Canvas.setRootType('cmpForm')`, не через палитру. `_renderPreview` пропускает корневой контейнер (`if (this.getRootContainer() === el) return;`).

## 6. Обязательные правки в ядре

После создания нового компонента **проверить** и при необходимости добавить:

### 6.1. `ide/canvas.js` → `CMP_TAGS`

Словарь восстановления camelCase из HTML, где тег в нижнем регистре:

```js
var CMP_TAGS = {
    'cmpaction':      'cmpAction',
    'cmpactionvar':   'cmpActionVar',
    // ...
    'cmpimage':       'cmpImage',       // ← добавить новое
    'cmpinfobox':     'cmpInfoBox'
};
```

Нужно, если пользователь может загружать HTML с тегом в нижнем регистре. Для новых компонентов IDE всегда пишет camelCase через `data-wb-tag`.

### 6.2. `ide/app.js` → `CMP_TAGS`

Тот же словарь (дублируется). Используется в `restoreCmpTags` при редактировании HTML через контекстное меню.

### 6.3. `ide/canvas.js` → `XML_SELF_CLOSE`

Если компонент самозакрывающийся:

```js
var XML_SELF_CLOSE = {
    // ...
    cmpimage: 1    // ← добавить
};
```

### 6.4. `ide/canvas.js` → `_injectIdeStyle`

Если компонент **невидимый**:

```js
'cmpaction, cmpdataset, …, cmpfetch, cmpfetchvar, cmpnewinvisible {' +
'  display: none !important; visibility: hidden !important;' +
'  pointer-events: none !important; user-select: none !important;' +
'}'
```

### 6.5. `ide/canvas.js` → `CDATA_CONTAINERS`

Если компонент хранит CDATA-контент:

```js
var CDATA_CONTAINERS = {
    cmpaction:1, cmpdataset:1, cmpscript:1, cmpsubaction:1,
    cmpnewcdata:1   // ← добавить
};
```

### 6.6. `ide/panels.js` → `PARENT_ONLY`

Если компонент имеет `parentOnly`:

```js
var PARENT_ONLY = {
    // ...
    cmpnewchild: 'cmpnewparent'   // ← добавить
};
```

### 6.7. `index.html`

Добавить подключение `index.js` в подходящую секцию:

```html
<!-- D3 controls -->
<script src="Component/d3/CheckBox/index.js"></script>
<script src="Component/d3/ComboBox/index.js"></script>
<script src="Component/d3/NewComponent/index.js"></script>
```

Порядок: родительский компонент до дочернего (для `parentOnly`). Остальное не критично.

## 7. CSS-превью: правила и подводные камни

### 7.1. Сброс IDE-рамки

Если `preview()` возвращает узел, IDE навешивает на него `[data-wb-preview]`, к которому применены глобальные стили:

```css
[data-wb-preview] {
    display: inline-block;
    outline: 1px dotted #b0bec5;
    outline-offset: 2px;
    padding: 1px 2px;
    margin: 1px;
    min-width: 12px;
    min-height: 12px;
}
```

Чтобы отменить эти стили для своего компонента, добавьте в `css/preview.css`:

```css
.my-preview[data-wb-preview] {
    outline: 1px dashed #90caf9 !important;
    outline-offset: 2px !important;
    padding: 0 !important;
    margin: 0 !important;
    min-width: 0 !important;
    min-height: 0 !important;
    display: inline-block !important;
}
```

**Важно:** селектор `[data-wb-preview]` даёт специфичность (0,1,0). Ваш селектор должен быть специфичнее, например `cmpMyComponent > [data-part="x"]` (0,1,1), иначе IDE-рамка перебьёт ваш outline.

### 7.2. Изоляция от родителя

`cmpMyComponent` — кастомный тег, по умолчанию `display: inline`. Если нужно блочное поведение, задайте явно:

```css
cmpMyComponent {
    display: block;
    position: relative;
    box-sizing: border-box;
}
```

### 7.3. Скрытие chrome-узлов, если они не должны быть видны

Chrome-узлы внутри компонента (созданы в `create()` с `data-wb-ide="1"`) видны в canvas. Если какие-то из них должны быть невидимы всегда — задайте `display: none` в preview.css:

```css
cmpMyComponent > [data-part="hidden-part"] {
    display: none;
}
```

Но чаще их надо **показывать** — они и есть визуальная часть компонента.

### 7.4. Скрытие пользовательских детей

Если компонент — контейнер, а его дети (например, `Column` внутри `Grid`) не должны рисоваться отдельно:

```css
cmpGrid > cmpColumn,
cmpGrid > cmpGridFooter {
    display: none !important;
}
```

### 7.5. Не использовать внешние ресурсы

Превью-CSS загружается в iframe. Внешние картинки, шрифты, FontAwesome могут не загрузиться. Используйте:
- inline-SVG (data-URL),
- CSS-фигуры (`::before`, `::after`, `border`, `background: linear-gradient`),
- системные шрифты (`Segoe UI`, `Consolas`, `Georgia`).

## 8. Чек-лист создания нового компонента

1. **Создать папку** `Component/d3/<Name>/` с подпапками `images/`, `css/`, `js/`.
2. **Положить иконку** `images/icon.png` (14×14).
3. **Написать `index.js`**:
   - `D3.register({...})` с `id`, `tagName`, `caption`;
   - `create()` — создать `<cmpXxx>` и добавить `data-wb-tag`;
   - `preview()` — либо вернуть DOM-узел, либо обновить chrome и вернуть `null`;
   - `properties` — разбить на группы через `{ type: 'separator', caption: '…' }`;
   - `events` — все события типа `code`. При необходимости каждому событию задать `template` (см. §3.4.1);
   - `styles: CS.STYLE_FIELDS.slice()` (или `[]` для служебных).
4. **Написать `css/preview.css`** — стили превью с обязательным сбросом IDE-рамки.
5. **Проверить/добавить правки в ядре** по разделу 6:
   - `CMP_TAGS` в `canvas.js` и `app.js`;
   - `XML_SELF_CLOSE` — если самозакрывающийся;
   - `_injectIdeStyle` — если невидимый;
   - `CDATA_CONTAINERS` — если содержит CDATA;
   - `PARENT_ONLY` в `panels.js` — если имеет ограничение на родителя.
6. **Подключить** в `index.html`.
7. **Проверить** в IDE:
   - компонент виден в палитре;
   - при вставке корректно отрисовывается в canvas;
   - в дереве отображается правильной подписью;
   - в инспекторе все поля корректно читают/пишут атрибуты;
   - **на вкладке Events двойной клик по пустому `select` создаёт функцию с ожидаемым телом (проверить и дефолт, и `template`)**;
   - при сохранении получается ожидаемый XML;
   - drag&drop в дереве соблюдает `parentOnly`.

## 10. Частые ошибки и как их избежать

| Ошибка | Последствие | Решение |
|---|---|---|
| Нет `data-wb-tag` на `create()` | `ComponentRegistry.match` вернёт `html.generic`, инспектор покажет чужие свойства | Всегда ставить `el.setAttribute('data-wb-tag', 'cmpXxx')` |
| Забыли `previewCss: [...]` | CSS-превью не загрузится в iframe | Проверить опцию и путь |
| `preview()` возвращает `undefined` | `_renderPreview` ничего не добавит, но и не удалит | Возвращать `null` для «нет превью», DOM-узел для «есть» |
| Не добавлен тег в `_injectIdeStyle` для невидимого | Компонент виден в canvas (пустой div) | Добавить в список |
| Не добавлен в `CMP_TAGS` | При загрузке HTML с `<cmpbadge>` camelCase не восстановится | Добавить в оба словаря |
| Chrome-узел без `data-wb-ide="1"` | Сериализуется в XML, дублируется на сервере | Помечать все служебные узлы |
| `parentOnly` только в `D3.register` | В дереве drag&drop не учитывает ограничение | Добавить в `PARENT_ONLY` в `panels.js` |
| `XML_SELF_CLOSE` не задан | Сериализуется как `<cmpImage></cmpImage>` | Добавить в словарь |
| CSS без `!important` на `[data-wb-preview]` | IDE-рамка перебивает стили | Использовать `!important` и специфичный селектор |
| Внешние картинки в preview.css | Не загружаются в iframe | Использовать inline-SVG или CSS-фигуры |
| `type: 'images'` в properties | Требует `D3.openImagesEditor` — не реализован | Использовать `type: 'code'` с JSON |
| `caption` со спецсимволами в атрибуте | Может сломать XML | Экранировать `&`, `"`, `<`, `>` при записи |
| `template` в событии без плейсхолдеров | Имя функции будет фиксированным, при повторном создании возникнет дубликат | Использовать `{name}` в имени функции |
| `template` без `Form.` при наличии `cmpScript` | Функция вставится как свободная — не привязана к форме | Проверить, что шаблон содержит `Form.{name}` или `{name}` в нужной форме |

## 11. Что НЕ нужно делать

- **Не создавать `<div>` в `create()` для компонентов, у которых есть свой кастомный тег.** Всегда `doc.createElement('cmpXxx')` — это гарантирует, что `data-wb-tag` сработает.
- **Не добавлять собственный `data-cmptype`, если не уверены.** `data-wb-tag` достаточно. `data-cmptype` используется как override для `ComponentRegistry.match` в специфичных случаях.
- **Не переопределять `preview()` для корневых контейнеров.** `_renderPreview` их пропускает. Если нужен chrome — рисуйте через CSS на самом теге (`::before`, `::after`).
- **Не использовать `<script>`-теги в preview.js для подключения внешних библиотек.** Canvas iframe не загрузит их. Вся логика превью — в самом `preview()`.
- **Не сериализовать CDATA вручную.** Используйте свойство `cdata` с `get`/`set`, IDE сама правильно отформатирует при сохранении.
- **Не забывать про `data-wb-ide="1"` на chrome-узлах.** Иначе они попадут в XML и сервер сгенерирует их дважды.
- **Не задавать `template` без плейсхолдера `{name}`.** Иначе при двойном клике на пустом `select` двух разных контролов будет создаваться одна и та же функция с одинаковым именем.

## 13. Алгоритм для нейросети

Для добавления нового компонента:

1. **Прочитать серверный `.inc`** — понять, какие атрибуты читаются, какая разметка генерируется.
2. **Прочитать клиентский `.js`** — понять поведение в рантайме (что делает `init`, какие методы публикуются).
3. **Определить категорию** компонента:
   - видимый / служебный / корневой;
   - контейнер / лист / void;
   - содержит CDATA / JSON / chrome-узлы / preview-узел.
4. **Составить список атрибутов** для `properties` — обычно это `Base::getProperties` + специфичные поля из `__construct`.
5. **Составить список событий** — из `D3Api.BaseCtrl.initEvent` и `extendEvent`. Для каждого события с нестандартным именем функции-обработчика задать `template` с плейсхолдерами `{name}`, `{event}`, `{ctrl}` (см. §3.4.1).
6. **Написать `create()`** — минимальная структура с `data-wb-tag`.
7. **Написать `preview()`** — либо реальный превью-узел, либо `null` с побочным эффектом обновления chrome.
8. **Написать `css/preview.css`** — с обязательным сбросом IDE-рамки и стилями компонента.
9. **Проверить** необходимость правок в `canvas.js`, `panels.js`, `app.js` по разделу 6.
10. **Подключить** в `index.html`.
11. **Запустить** в IDE и убедиться, что компонент виден, вставляется, редактируется, и что двойной клик на пустом `select` события создаёт функцию с ожидаемым телом (или дефолтную, если `template` не задан).
12. **Сохранить** — XML должен содержать компонент в ожидаемом виде.

При неясностях — ориентироваться на аналогичный компонент из существующих (см. раздел 12).
